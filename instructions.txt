This describes how you use tmux-injector tools. This is how the system works.

Panes are the user's live terminal sessions.
Same shell, same aliases, same PATH, same environment as if the user typed directly.
Not a sandboxed subprocess — commands have real consequences in the user's environment.

==========
1. TOOL SELECTION
==========

┌─ Start interpreter (python3, openroad, etc.)
│   └─→ xsh_peek / xpy_peek / xtcl_peek
│       wait=1~2 seconds — OR — poll="prompt_pattern" to wait for a specific prompt
│
├─ Run short command (wait for completion)
│   └─→ xsh / xpy / xtcl (blocking)
│
├─ Run long task (need monitoring)
│   └─→ xsh_start / xpy_start / xtcl_start (non-blocking)
│       then task_status / task_output / task_wait
│
├─ Respond to prompt (password, yes/no)
│   └─→ send_text (plain text, sends Enter by default)
│
├─ Send special keys (C-c, Escape, arrows)
│   └─→ send_keys (no Enter by default)
│
├─ Reset pane (kill process, fresh shell)
│   └─→ respawn_pane (cleans tasks/locks, keeps registration)
│       cmd= to start specific process after reset
│
├─ Check current screen
│   └─→ capture_pane
│
├─ Wait for specific output to appear (no task_id)
│   └─→ poll_pane (blocks until pattern matched or timeout)
│       fresh=True (default): ignores pre-existing content
│       fresh=False: also matches pre-existing content
│
│       fresh rule:
│         After respawn_pane(cmd=) / create_session(cmd=) → fresh=False
│           cmd= starts process before poll_pane runs → output already on screen
│         After xsh_peek / send_text → fresh=True (default)
│           output arrives after poll_pane starts watching
│
└─ Check sessions, processes, GPU memory
    └─→ ls (compact overview), ls(session=, gpu=True) (detailed + GPU)

==========
2. COMMON PATTERNS
==========

Starting an interpreter and running code:
    xsh_peek(pane, "python3", wait=1)      # start interpreter
    xpy(pane, "print('hello')")            # run code (blocking)
    xpy_peek(pane, "exit()", wait=1)       # exit interpreter

Starting a long-running script:
    xsh_peek(pane, "python3", wait=1)      # start interpreter first
    xpy_start(pane, file="train.py")       # returns task_id for monitoring

Waiting for long-running tasks:
    task_id = xpy_start(pane, file="train.py")
    task_wait(task_id=task_id, timeout=300)

    # Multiple parallel tasks:
    task_wait(task_ids=[id1, id2], race=True, timeout=300)
    # race=True: returns when first task completes

    # capture_pane polling loop is an anti-pattern when task_id exists.
    # task_wait with timeout replaces repeated capture_pane calls.

Waiting for specific output (no task_id):
    xsh_peek(pane, "make build", wait=1)
    poll_pane(pane, pattern="Build complete|ERROR", timeout=120)
    # fresh=True (default): only matches NEW output after poll_pane is called
    # if the pattern already exists in pane before the call, it is IGNORED

After respawn/create with cmd= (process starts immediately):
    respawn_pane(pane, cmd="python3")
    poll_pane(pane, pattern=">>>", fresh=False)
    # cmd= starts python3 before poll_pane runs → ">>>" already on screen
    # fresh=True here would timeout (ignores the already-printed ">>>")

SSH connection:
    xsh_peek(pane, "ssh user@host", poll="\\$", poll_timeout=15)  # wait for shell prompt
    send_text(pane, "password")          # if password required
    xsh(pane, "hostname")

Passing variables from REPL to script (globals trick):
    xpy(pane, "model_path = '/path/to/model'")
    xpy_start(pane, file="train.py")       # script accesses via globals().get('model_path', None)
    # file= uses exec() which shares REPL's globals()

Setting up parallel workspaces:
    create_session("exp", windows=["a", "b", "c"], cmd="python3")
    # 3 windows, each running python3, all panes auto-registered

    create_session("exp", windows=["a", "b"], cmds=["python3", "bash"])
    # per-window commands: window a→python3, window b→bash

==========
3. PANE REGISTRATION (REQUIRED)
==========

Panes must be registered before use.

    set_pane("t1:1.0", "description")
    ls()

"Pane not registered" error → ls() first, then re-register if needed.

==========
4. MULTI-PANE OPERATIONS
==========

All x* tools accept panes= for parallel dispatch.
code= sends the same code to all panes. codes= sends different code per pane (1:1 indexed).

Same code to all:
    xpy(panes=["t1:a.0", "t1:b.0"], code="print('hello')")

Different code per pane:
    xpy(panes=["t1:a.0", "t1:b.0"], codes=["x=1; print(x)", "x=2; print(x)"])

Works with all 9 tools: xpy/xtcl/xsh, xpy_start/xtcl_start/xsh_start, xpy_peek/xtcl_peek/xsh_peek.

code and codes are mutually exclusive. cmd and cmds are mutually exclusive.
codes/cmds length must match target count.

==========
5. CODE LIMITATIONS
==========

Python (xpy/xpy_start/xpy_peek): literal \n in code is OK (base64 encoding).
TCL (xtcl/xtcl_start/xtcl_peek): literal \n still breaks injection.

All tools use exec(). Bare expressions produce no output. file= also uses exec().
    xpy(pane, "x") → empty. Use print(x).

file= path is resolved relative to the client's (agent's) working directory, not the tmux pane's cwd.
    xpy_start(pane, file="train.py")  # resolves to /home/user/project/train.py if agent cwd is /home/user/project
    # The pane's cwd is irrelevant for file= resolution.

Do not use import/reload in REPL. Use file= instead.
    xpy(pane, file="/path/to/module.py")

Compound statements (for/if/while/def/class/with/try) require triple-quoted strings.
Semicolons work only for simple statements.
    xpy(pane, """
    for x in range(10):
        print(x)
    """)

==========
6. capture_pane: tail AND grep
==========

tail= defines the visible window. grep= searches within that window.
    capture_pane(pane, tail=30)                    # last 30 lines
    capture_pane(pane, tail=30, grep="ERROR")      # last 30 lines, then grep
    capture_pane(pane, grep="ERROR")               # last 100 lines (default), then grep

grep does NOT expand the capture range. To search deeper scrollback, increase tail:
    capture_pane(pane, tail=4000, grep="FATAL")    # search last 4000 lines

==========
7. STATE TRACKING
==========

Pane state is tracked in memory. capture_pane is not called before every command.

State changes to remember:
- xsh_peek(pane, "python3") → pane is now Python REPL (>>>)
- xpy_peek(pane, "exit()") → pane is now bash ($)
- xsh_peek(pane, "openroad") → pane is now TCL (%)
- xtcl_peek(pane, "exit") → pane is now bash ($)
- send_keys("C-c C-c") → uncertain, capture_pane to confirm
- respawn_pane(pane) → pane is now bash ($), all tasks cleaned

capture_pane is used when:
- First time accessing a pane in this conversation
- After Ctrl+C interrupt (state uncertain)
- After abort/timeout from blocking tools (use task_list to find converted task)

capture_pane is NOT for polling task progress.
When task_id exists (from xpy_start/xsh_start/xtcl_start), use task_wait.

==========
8. ABORT/TIMEOUT BEHAVIOR
==========

All x* tools send code to tmux before waiting for output.
Any interruption — timeout, abort, user reject, cancel — means code was already sent.
After interruption: capture_pane first. Do not send another command until pane state is confirmed.

Timeout behavior:
    Blocking tools (xsh/xpy/xtcl) return [timeout] on timeout — no task created.
    Process may still be running in tmux. Use xsh_start next time for long-running commands.

User cancellation (CancelledError) auto-converts to background task.
After cancellation: task_list() to find the converted task, then task_wait/task_output.

Exit commands produce no end marker. Use peek for exit:
    xtcl_peek(pane, "exit", wait=1)

task_wait returning [error]:
    Pane died during task execution (crash, kill, etc.).
    task_output(task_id) shows the exact tmux error reason.
    Recovery: ls() to check pane state → if alive, reuse directly.

task_cancel removes tracking only — execution in tmux continues.
To actually stop: send_keys(pane, "C-c") first, then task_cancel.

==========
9. CONVERSATION CONTINUITY
==========

Registered panes persist in MCP server memory across conversation compaction.
After compaction: ls() to check what is registered.
New session or server restart: ask user which pane to use.


==========
10. OWNERSHIP MODEL
==========

set_pane() auto-registers the session/window as "external".
create_session()/create_window() registers as "managed".

tmux kill-session, tmux kill-window via Bash: NEVER used.
All session/window lifecycle is through MCP tools only.

External sessions are user-owned. Structure modification (create_window, kill_window)
on external sessions does not occur.
New workspaces → create_session(). Existing external panes → set_pane() to register.

Temporary work (one-off ssh, sync, file transfer, etc.):
    create_session("tmp") → work → kill_session("tmp")

    Existing user panes are never borrowed for temporary work.
